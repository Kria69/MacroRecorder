# Macro Recorder Pro

Windows-приложение для записи и воспроизведения действий клавиатуры и мыши.

Поддерживаемые системы:

- Windows 10 x64;
- Windows 11 x64;
- Windows 11 ARM, включая запуск в Parallels Desktop.

## Исправленные ошибки

### 1. Синтаксическая ошибка в русской локализации

**Проблема:** в `i18n.py` отсутствовала запятая между переводами `log_cannot_change_profile` и `layout_suffix`. Из-за этого приложение не запускалось с ошибкой `SyntaxError`.

**Решение:** добавлена пропущенная запятая. Русская локализация теперь корректно импортируется.

### 2. Ошибка инициализации логгера

**Проблема:** `self.logger` использовался в конструкторе `MacroApp` до создания логгера. Это приводило к ошибке:

```text
AttributeError: 'MacroApp' object has no attribute 'logger'
```

**Решение:** первое сообщение записывается только после вызова `setup_logging()`.

### 3. Профиль не успевал сохраниться

**Проблема:** сохранение выполнялось в daemon-потоке. При закрытии приложения поток мог завершиться до окончания записи gzip-файла.

**Решение:** сохранение профиля выполняется синхронно. После нажатия «Сохранить» запись гарантированно завершается. После успешной операции в журнал добавляется сообщение о сохранении.

Профили хранятся в:

```text
%APPDATA%\\MacroRecorder\\profiles\\
```

### 4. Очистка профиля снова сохраняла пустой профиль

**Проблема:** после очистки профиля вызывался `save_current_profile()`, поэтому пустой профиль повторно записывался на диск.

**Решение:** очистка теперь удаляет файлы профиля `profile_N.json.gz` и старый вариант `profile_N.json` вместо сохранения пустых данных.

### 5. Неправильная запись комбинации Alt+Shift

**Проблема:** при записи комбинации из нескольких модификаторов первый отпущенный модификатор удалялся из списка активных клавиш. Например, `Alt+Shift` сохранялся как одиночный `Shift`.

**Решение:** запись теперь сохраняет всю комбинацию модификаторов как одно событие `modifier_combo`. В профиль добавляется признак `language_switch` для комбинаций переключения раскладки.

### 6. Неправильное воспроизведение modifier combo

**Проблема:** все события `modifier_combo` воспроизводились через системную комбинацию переключения языка. Поэтому одиночный `Ctrl`, `Alt` или `Shift` мог неожиданно переключать раскладку.

**Решение:**

- одиночные модификаторы воспроизводятся как одиночные клавиши;
- обычные комбинации воспроизводятся из реально записанных модификаторов;
- комбинации переключения языка используют системное сочетание, определённое Windows.

### 7. Системная комбинация переключения языка определялась неправильно

**Проблема:** приложение использовало фиксированное `win+space` или запасное сочетание, даже если в Windows была настроена другая комбинация, например `Alt+Shift`.

**Решение:** системная комбинация читается из реестра Windows по адресу:

```text
HKEY_CURRENT_USER\\Control Panel\\Input Method\\Hot Keys
```

Если Windows не возвращает настройку, используется `win+space` как запасной вариант.

### 8. Раскладка не переключалась перед воспроизведением

**Проблема:** сравнивалась раскладка потока самого приложения, а не активного пользовательского окна. Из-за этого приложение могло считать раскладку синхронизированной, хотя в целевом окне она была другой.

**Решение:**

- при записи запоминается раскладка окна с фокусом;
- перед воспроизведением проверяются раскладки окна с фокусом и foreground-окна;
- поток самого Macro Recorder больше не используется для подтверждения синхронизации;
- сначала отправляется `WM_INPUTLANGCHANGEREQUEST` для выбора конкретной HKL;
- затем выполняется проверка результата;
- при необходимости используется системная комбинация переключения;
- добавлены повторные попытки и итоговая проверка.

Сообщение «Раскладка синхронизирована» показывается только после успешной проверки активного окна.

### 9. Заглавные буквы воспроизводились некорректно

**Проблема:** для заглавных букв добавлялся искусственный `Shift`, но события отпускания клавиши обрабатывались неправильно. Это могло оставлять клавиши в некорректном состоянии.

**Решение:** синтетический `Shift` отслеживается отдельно, а лишние события отпускания не добавляются. Состояние клавиш очищается после завершения записи.

### 10. Воспроизведение долго не останавливалось

**Проблема:** перед следующим событием выполнялся непрерывный `time.sleep()`. При большой задержке Stop не срабатывал сразу.

**Решение:** задержка выполняется через `threading.Event.wait()`. Кнопка Stop теперь может прервать ожидание немедленно.

### 11. Повреждённая конфигурация горячих клавиш могла сломать настройки

**Проблема:** произвольные ключи и значения из `hotkeys_config.json` без проверки объединялись с настройками приложения. Отсутствующие или некорректные значения могли вызвать `KeyError` или `AttributeError`.

**Решение:** загружаются только известные ключи с непустыми строковыми значениями. Некорректные записи заменяются значениями по умолчанию.

### 12. Изменение профиля во время воспроизведения

**Проблема:** профиль можно было переименовать или очистить во время записи/воспроизведения. Поток воспроизведения мог получить изменённые данные.

**Решение:** во время записи, запуска и воспроизведения запрещены:

- выбор другого профиля;
- переименование профиля;
- очистка профиля;
- импорт профиля.

Имя профиля фиксируется в начале воспроизведения.

### 13. Некорректные timestamps в профиле

**Проблема:** Python считает `True` и `False` подклассом `int`, поэтому булевы значения принимались как время события.

**Решение:** булевы timestamps явно отклоняются при импорте и загрузке профиля.

### 14. Чрезмерно подробные INFO-логи

**Проблема:** в обычном режиме в лог попадало слишком много технической информации: события мыши, попытки синхронизации, внутренние этапы playback и регистрации hotkeys.

**Решение:**

- обычный уровень логирования установлен на `INFO`;
- технические подробности переведены на уровень `DEBUG`;
- включение Debug Mode переключает логирование на `DEBUG`;
- выключение Debug Mode возвращает уровень `INFO`.

Старые log-файлы не изменяются. Новые файлы логов используют обновлённые уровни.

## Автоматические тесты

Файл тестов:

```text
test_automatic.py
```

Тесты проверяют:

- отклонение булевых timestamps;
- проверку порядка событий;
- импорт JSON-профиля;
- импорт gzip-профиля.

Файл автоматического тестирования создан. На момент добавления он не запускался по просьбе заказчика.

Для запуска в будущем:

```bash
python -m unittest -v test_automatic.py
```

## Установка

Требуется Python 3.10+ и Windows.

```bash
pip install -r requirements.txt
```

## Запуск

```bash
python run.py
```

Для глобальных хуков клавиатуры и мыши Windows может потребоваться запуск с повышенными правами.

## Проверка синтаксиса

```bash
python -m compileall -q .
```

Проверка синтаксиса проекта после исправлений проходит без ошибок.
